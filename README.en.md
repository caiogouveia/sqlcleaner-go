# sqlcleaner-go

*[Leia em português](README.md)*

Go port of [`sqlcleaner`](https://github.com/caiogouveia/sqlcleaner) (Python): utilities for streaming PostgreSQL SQL dumps without loading the whole file into memory — aiming for a single static binary, requiring neither Python nor `pigz` on the target machine. `analisar`/`remover`/`esvaziar`/`truncar`/`set` operate 100% locally and never open a database connection; the exception is `restaurar`, which applies the dump (already cleaned up by the other commands, if applicable) directly to a PostgreSQL server via a native driver (`pgx`), also without depending on `psql`/`pg_restore` being installed.

**WARNING:** This is experimental software, developed mostly with AI. Use at your own risk.

See `docs/plano-migracao-go.md` for the history of architectural decisions behind this port (in Portuguese).

## Installation

### Via Homebrew (macOS/Linux)

```bash
brew tap caiogouveia/sqlcleaner
brew install --cask sqlcleaner-go
```

### Build from source

```bash
go build -o sqlcleaner ./cmd/sqlcleaner
# or, via Makefile:
make build
```

Requires only the Go toolchain — no system dependencies (parallel gzip is done in pure Go via `pgzip`, without relying on the `pigz` binary).

### Pre-built binary

You can also download the binary directly from the [releases page](https://github.com/caiogouveia/sqlcleaner-go/releases) (linux/darwin/windows, amd64/arm64), without needing Homebrew or the Go toolchain.

## Language

Messages, help (`--help`) and errors are in Portuguese by default, with English available via `--lang=en`:

```bash
sqlcleaner --lang=en analisar dump.sql
# or, to set it without repeating the flag every time:
export SQLCLEANER_LANG=en
```

Resolution order: `--lang` > `SQLCLEANER_LANG` > system `LC_ALL`/`LANG` > Portuguese (default). Subcommand names (`analisar`, `remover`, `esvaziar`, `truncar`, `set`) do not change with the language.

## Usage

```bash
sqlcleaner analisar  dump.sql[.gz] [-n TOP]
sqlcleaner remover   dump.sql[.gz] -o output.sql[.gz] -t table1,table2
sqlcleaner esvaziar  dump.sql[.gz] -o output.sql[.gz] -t table1,table2
sqlcleaner truncar   dump.sql[.gz] -o output.sql[.gz] -t table:N:ORDER -n DEFAULT_LIMIT
sqlcleaner set       dump.sql[.gz] -o output.sql[.gz] -p param1,param2
sqlcleaner restaurar dump.sql[.gz] --dsn postgres://user:password@host:5432/db [--create-db] [--dry-run] [-y] [--jobs N]
```

### `analisar` — lists tables by size

Measures bytes and rows of each `COPY` block, sorted from largest to smallest.

```bash
sqlcleaner analisar dump.sql
sqlcleaner analisar dump.sql.gz -n 20
```

### `remover` — completely removes tables

Removes data (`COPY`), structure (`CREATE TABLE`, `CREATE SEQUENCE`) and related objects (`ALTER TABLE`/`ALTER SEQUENCE`, `CREATE INDEX`).

```bash
sqlcleaner remover dump.sql -o dump_clean.sql -t log,cache
```

**Limitation:** does not remove tables that have foreign-key dependencies from tables that remain in the dump.

### `esvaziar` — deletes only the data

Keeps `CREATE TABLE`, sequences, indexes and constraints; removes only the rows inside `COPY … \.`, preserving the header and terminator.

```bash
sqlcleaner esvaziar dump.sql -o dump_no_data.sql -t log,cache
```

### `truncar` — caps rows per table

Keeps the structure and N rows per table, discarding the rest. A global limit (`-n`) and/or a per-table limit (`table:N`) can be combined. Format of each entry in `-t`: `table`, `table:N`, `table:ORDER` or `table:N:ORDER`. `ORDER` is `ASC` (default, keeps the **first** N rows of the `COPY` block) or `DESC` (keeps the **last** N — useful for log/audit-style tables when you want the most recent rows). The order is positional within the `COPY` block, not a column `ORDER BY`.

```bash
sqlcleaner truncar dump.sql -o output.sql -t log:1000,cache -n 500
sqlcleaner truncar dump.sql -o output.sql -t log:1000:DESC,cache
sqlcleaner truncar dump.sql -o output.sql -t audit_log:DESC -n 200
```

### `set` — removes SET parameters

Removes `SET <parameter> = ...;` (or `TO ...;`) lines — useful when the dump was generated by a newer PostgreSQL version than the target server (e.g. `transaction_timeout`).

```bash
sqlcleaner set dump.sql -o dump_clean.sql
sqlcleaner set dump.sql.gz -o dump_clean.sql.gz -p transaction_timeout,idle_in_transaction_session_timeout
```

### `restaurar` — applies a dump to a PostgreSQL server

Restores a `.sql`/`.sql.gz` dump (the same format produced/edited by the other commands) to a target PostgreSQL server, via a native driver (`pgx`) — does not depend on `psql`/`pg_restore` being installed. It indexes the dump once (SQL chunks and `COPY` blocks, by byte offset) and applies them in order: sequential SQL, with adjacent `COPY` runs executed in parallel with each other (`--jobs`).

```bash
sqlcleaner restaurar dump_clean.sql.gz --dsn postgres://user:password@host:5432/db
sqlcleaner restaurar dump.sql --dsn postgres://user:password@host:5432/new_db --create-db
sqlcleaner restaurar dump.sql --dsn postgres://user:password@host:5432/db --dry-run
sqlcleaner restaurar dump.sql --dsn postgres://user:password@host:5432/db -y --jobs 8
```

- `--dsn`: connection string (URL or `key=value`). If omitted, uses the `PGHOST`/`PGPORT`/`PGUSER`/`PGPASSWORD`/`PGDATABASE` environment variables, just like `psql`.
- `--create-db`: creates the target database if it doesn't already exist.
- `--dry-run`: only indexes the dump and lists the tables/sizes that would be restored, without touching the database.
- `-y`/`--yes`: skips the interactive confirmation prompted when the target database already has tables (avoids accidentally overwriting data).
- `--jobs`: parallelism of the data phase (default: 4).

**Limitation:** assumes a well-formed `pg_dump --format=plain` dump (not the custom/directory format). Errors from PostgreSQL itself during the restore (e.g. table already exists, constraint violation) are reported as they came from the server.

**Supported PostgreSQL versions:** the `pgx/v5` driver used internally follows the same official support range as the PostgreSQL team — major releases from the last 5 years, currently **PostgreSQL 14 onward**. Manually tested end-to-end (real dump via `pg_dump` → `truncar` → `restaurar`) against `postgres:14-alpine`, `postgres:16-alpine` and `postgres:18-alpine`, all passing. Versions ≤13 probably work (the protocol used — simple/extended query and `COPY` — has been stable for decades), but are not tested or officially supported by `pgx`.

## Quoted identifiers / names with uppercase letters or a literal dot

Just like `pg_dump`, identifiers can come quoted with double quotes (`"Table"`, `"Schema"."Table"`) for names with uppercase letters or special characters. Without an explicit schema, `table` matches `public.table` or an unqualified name. An unquoted dot in `-t` is always a schema.table separator — table names with a literal dot need quotes (inside the shell: `-t '"name.with.dot"'`).

## Tests

```bash
go test ./...
```

The `restaurar` integration test (`cmd/sqlcleaner/restaurar_integration_test.go`) runs against a real PostgreSQL: it creates a disposable database, restores a dump into it, checks the data and tests the safety confirmation. It only runs if the `SQLCLEANER_TEST_DSN` environment variable is set — without it, it's skipped (`go test ./...` works normally without Postgres installed).

```bash
make test-integration                                  # spins up postgres:16-alpine via Docker, runs the test, tears the container down
make test-integration PG_TEST_IMAGE=postgres:14-alpine # test against another version
```

Or manually, against any Postgres already available:

```bash
SQLCLEANER_TEST_DSN=postgres://postgres:postgres@localhost:5432/postgres go test ./cmd/sqlcleaner/... -run Integration -v
```

## Architecture

The `internal/sqldump` package holds the logic shared across the dump-editing subcommands: identifier parsing (`ParseQualifiedName`/`ReadIdentifier`), target-name matching (`FindMatchingTarget`/`FindConfig`), `.sql`/`.sql.gz` reading/writing (`OpenReader`/`OpenWriter`, via `pgzip`) and size formatting (`FormatSize`). The `internal/sqlrestore` package handles only `restaurar`: indexing the dump into SQL/COPY segments by byte offset, connection resolution (`pgconn`), and the actual apply step (sequential for SQL, parallel for batches of `COPY`). Subcommands live in `cmd/sqlcleaner/`, one per ported script (plus `restaurar`, which has no equivalent in the original Python `sqlcleaner`).
